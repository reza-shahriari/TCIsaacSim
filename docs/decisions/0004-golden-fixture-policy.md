# ADR 0004 — Golden fixture policy

**Status:** Accepted
**Date:** 2026-09-10

## Context

Outputs with no analytic answer — a full stage render on a synthetic G-buffer, an AGC output, a LUT
slice — can only be protected by regression against a stored reference. Golden tests are also the
easiest tests to turn into a liability: exact-equality comparisons that break on a libm update,
references nobody can tell apart from a genuine physics regression, and failures that leave nothing to
inspect. `make golden-update` existed in the Makefile but no conftest registered `--update-golden`.

## Options considered

1. **Exact-equality `.npy` files, regenerated by hand** — simplest; breaks on harmless float noise and
   hides the difference between "the inputs changed" and "the physics changed".
2. **`.npy` + JSON sidecar with the producing config hash and a stated tolerance** — one extra file per
   golden; makes STALE (inputs changed) and FAILING (values changed) distinguishable and forces every
   comparison to state a tolerance in the array's units.
3. **Image-format goldens (PNG) for visual diffing** — human-friendly but 8-bit, so it cannot hold a
   radiance or temperature array without violating non-negotiable #2.

## Decision

Option 2, implemented in `tests/golden/conftest.py`:

- A golden is `tests/golden/data/<name>.npy` plus `<name>.json` recording `config_hash`, dtype, shape,
  the tolerance it was accepted at, its units and the NumPy version.
- Storable dtypes are **float32, uint16 and uint8** (uint8 is what the ISP emits). float16 is refused
  with the non-negotiable #2 message, on write *and* on load, so a hand-edited file cannot slip in.
  float64 is refused so that a golden records what the pipeline emits rather than a promoted copy.
- `check()` requires `atol` and/or `rtol`; exact equality is a `ValueError`.
- Outcomes are distinct exceptions: **STALE** (`GoldenStaleError`, hash differs — the message names
  both hashes and the regenerate command) is raised **before** values are compared, so a config change
  can never be misread as a physics regression; **FAILING** (`AssertionError`) writes the actual array
  to `outputs/golden/<name>.actual.npy` and prints both paths plus the worst element; **MISSING**
  (`FileNotFoundError`) says how to create the golden.
- STALE **fails** rather than skipping. A skip would silently drop coverage the moment any input
  changed; a distinct failure costs one deliberate `make golden-update` and keeps the intent visible in
  the commit that regenerates.
- `--update-golden` is registered in the root `tests/conftest.py` so it exists whichever directory
  pytest is pointed at; regeneration goes through `make golden-update` only.
- **`tests/golden` joins the default gate** (`make test` and therefore `make check`). Golden comparisons
  are array compares in milliseconds; the gate must be the place regressions surface. `slow`-marked
  tests remain deselectable but are not excluded by default.
- The config hash for goldens produced from literal dictionaries is the SHA-256 of canonical JSON
  (`config_hash`); the sensor-config hash with file-content substitution arrives with the YAML loader
  (ADR 0008) and will be used in its place for goldens produced from real configs.

## Consequences

Each golden costs two committed files and a tolerance decision. Regenerating a golden in the same commit
as a behaviour change is allowed only when the commit body says so. There is no error introduced by this
decision; the tolerances belong to the individual goldens and are recorded in their sidecars.

## Revisit when

Golden arrays exceed a few MB each (consider Git LFS or generated-not-committed, as for LUTs in ADR 0012),
or the golden suite pushes `make test` past its 5 s budget.
